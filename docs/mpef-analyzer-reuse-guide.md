# MPEF Analyzer — Reuse & Redeployment Guide

**Applies to:** engine v2.6 · offline edition (`mpef-analyzer-offline.html`) and connected edition (`mpef-analyzer.html`)
**Audience:** anyone who wants to run, distribute, customize, or redeploy the app in a new environment.

---

## 1. What this app is

The MPEF Analyzer turns meeting artifacts — agenda, transcript, minutes (MoM), chat log, attendance log — into an objective productivity report: a 0–100 Meeting Productivity Index (MPI), six weighted dimension scores, an agenda coverage map, presenter and participation tables, an outcomes register, and evidence-cited flags. It implements the Meeting Performance Evaluation Framework (MPEF) v1.0.

Its core design rule: **extraction finds evidence; deterministic code computes every number.** Anything the supplied artifacts cannot truly support is reported *Not Assessable* — never estimated. Same inputs + same configuration ⇒ same report, always.

Everything is one self-contained HTML file per edition. There is no build step, no dependency, no install, and no data storage: nothing is saved between sessions and (in the offline edition) nothing ever leaves the device.

## 2. The two editions

| | Offline edition | Connected edition |
|---|---|---|
| File | `mpef-analyzer-offline.html` | `mpef-analyzer.html` |

| Where the Claude button works | n/a | Only while the file runs as an artifact inside Claude, online |

Scoring code and configuration are identical in both, so the same evidence produces the same scores in either edition.

## 3. The three extraction routes

**Route A — Extract & score locally (works everywhere, fully offline).** A deterministic rule engine parses the pasted artifacts and the scoring code renders the dashboard. Accepted transcript shapes, auto-detected and normalized: `[10:04] Name: text`, `Name [10:04]: text`, `Name: text`, `10:04 Name: text`, WebVTT (including Teams/Zoom `<v Name>` voice tags), SRT (numbered cues, `-->` timing lines), block-format exports where the speaker sits on its own header line above the speech — in **either** order and at any timestamp precision (`Sara 0:04`, `02:32:23  The respective team`) — and caption files with no speaker names at all (people-dependent metrics then report n/a). A block header's speaker label need not be a title-case person name (v2.3): "The respective team", "PMO lead" and "Facilitator" are all accepted, bounded by a 5-word/48-character cap and a no-terminal-punctuation test so a line of speech is never mistaken for a speaker. Any size — 300k+ characters parse in well under a second.

**Route B — Any-AI route (extraction anywhere, scoring stays local).** "1 · Copy extraction prompt" (or "Save as .txt" for very large transcripts) produces a ready prompt embedding the pasted artifacts and the canonical JSON schema. Run it in any capable AI chat, paste the returned JSON into step 2, press "3 · Score pasted JSON". Best extraction quality for messy or summarized transcripts.

**Route C — Analyze with Claude (connected edition only).** Two parallel schema-constrained extraction calls with automatic retry/backoff for rate limits, plus automatic fallback to Route A when input exceeds ~60k characters or the API rejects it as too large.

The local engine also writes its extraction JSON into the editable step-2 box, so users can inspect, correct any count, and re-score instantly — regardless of route.

## 4. Honest-measurement rules built into v2.6

These exist so scores are never artifacts of note-taking; they are the answer to "why is this metric n/a?":

1. **Condensed-transcript detection.** If transcribed words cover under 50% of the floor time, pace, filler density, monologue ratio, and turn density are Not Assessable (a summary can't reveal them).
2. **Timestamp resolution.** Response latency requires second-level timestamps (`HH:MM:SS`); minute-level stamps mark it n/a.
3. **Attendance grounding.** Attendance rate, retention, and active-contributor ratio require attendance data (log pasted, or `minutes_present` in pasted JSON) — silent attendees are invisible in a transcript, so speaker-only data would fake these.
4. **Audio-only signals.** Dead time / silence and interruption overlaps are never scored from text.
5. **Off-agenda by keyword proximity.** Local extraction scores off-agenda ratio by classifying each substantive utterance (≥8 words, so backchannel is never judged) as off-agenda when it matches none of the agenda's keywords — always with a disclosure note that this is proximity matching, not semantic understanding. A manually-entered value (Advanced evidence card) always overrides it. Route B/C still provide true semantic mapping. Since v2.1, each off-agenda entry on a participant's detail page names the actual keyword list it was checked against (`quality.agenda_keywords`), instead of asserting the verdict bare.
6. **Zero-count honesty.** A detector finding nothing is absence of evidence, not evidence of zero: `feedback_instances` is Not Assessable (not a scored 0) when no praise/agreement phrases are detected.
7. **Found vs. discussed (v1.5).** An agenda item's status distinguishes two different failures the old single "skipped" label conflated: an item the matcher couldn't locate anywhere in the transcript (**not found** — likely different wording than the agenda, flagged by name so you can check and correct it) from one that *was* located but wasn't real discussion (**skipped**). Coverage rate counts both as not-covered — a genuinely skipped item is equally unlocatable, so excluding either would gut the metric — but only "skipped" is a claim about what happened in the meeting.
8. **Sample-size transparency.** Ratio metrics display their counts (e.g. `100% · 1/1`); tiny denominators can legitimately score 0 or 100 and are visibly thin.
9. **Not-a-name guard.** Lines like `Decision: …` or `Action: …` are never mistaken for speakers.
10. **Decisions are verified, not just pattern-matched (v1.6).** A candidate decision has to survive a set of explicit disqualifiers — it's a question, a negation ("we haven't agreed"), a hypothetical ("if we approved…"), an unadopted proposal ("we should approve"), a deferral to a later date, or bare assent with no stated outcome ("Agreed.") — before it's counted. This is still keyword/pattern proximity, not semantic understanding, so it's a disclosed approximation like the rest of the local engine, not a claim of perfect precision.
11. **Arabic capture is a full second lexicon, not a fallback (v2.0).** Speaker names, decisions, actions, deferrals, risks, feedback and the agenda-anchoring stemmer all run an Arabic pattern set alongside the English one — matched per token, so a code-switched sentence ("اتفقنا — we ship the API by Friday") is caught by whichever language it's actually in. Filler-word detection stays English-only (no reliable Arabic filler lexicon exists yet), so it's marked Not Assessable — not a false zero — the moment a transcript is majority Arabic, with a disclosure note naming the language mix.
12. **One speaker, one spelling, independent of case (v2.5).** "Sara" and "sara" fold to the same participant, credited to the capitalized spelling — talk minutes, Q&A pairing, agenda ownership, decisions, actions, chat and attendance all key off the folded identity, so a case variant can never split one person into two or turn a self-answer into a real exchange. Recognizing a lowercase label is anchored to an already-established capitalized speaker, never a blanket relaxation, so ordinary prose still can't parse as a speaker.

The flags panel states which of these rules fired and why, prioritizing meeting-specific findings over generic ones when more than the agent spec's 6-note budget fire in one run (§2 of the agent spec: "notes <=6").

## 5. Deploying to other environments

**Single laptop (offline).** Copy `mpef-analyzer-offline.html` (or the zip) to the machine; double-click. Requirements: any evergreen browser (Chrome, Edge, Firefox, Safari) from recent years. No admin rights needed.

**Email / chat distribution.** Send `MPEF-Analyzer-Offline.zip` (contains the app + README + these docs). Zipping avoids mail filters that block bare `.html`.

**Shared drive / SharePoint / USB.** Drop the file anywhere users can open it. It runs from `file://` with full functionality.

**Intranet static hosting.** It is a static asset: place the file on any web server (nginx, Apache, IIS, S3/静态 bucket, GitHub Pages, SharePoint page). No backend, no database, no cookies. Suggested headers: standard static caching plus `Content-Security-Policy` if your org requires one — the offline edition needs no external origins at all.

**Inside Claude.** Paste or attach `mpef-analyzer.html` in a Claude chat so it renders as an artifact; the "Analyze with Claude" button works there with no key handling.

**Re-enabling the AI route on your own infrastructure.** The connected edition's keyless call works only inside Claude. To offer model extraction elsewhere, stand up a tiny proxy that holds your API key server-side and forwards the request, then point the app at it:

```js
// in mpef-analyzer.html, inside callClaude():
const res = await fetch("https://YOUR-PROXY.example.com/v1/messages", { ... });
```

The proxy must inject the provider's auth headers, pass through `{model, max_tokens, messages}`, and return the JSON body unchanged; allow CORS from your hosting origin. Never embed an API key in the HTML — anyone can read it. Alternatively, skip the proxy entirely: Routes A and B already cover every environment.

## 6. Configuration & customization

All scoring behavior lives in one `CONFIG` object near the top of the `<script>` block — edit, save, reload:

| Key | Default | Meaning |
|---|---|---|
| `weights` | D1 20 · D2 15 · D3 20 · D4 20 · D5 10 · D6 15 | Dimension weights for the MPI |
| `bands.startDelay` | 15 → 0 | Minutes late: worst (=0 pts) → best (=100 pts) |
| `bands.overrun` | 0.50 → 0 | Fraction of scheduled length |
| `bands.dead` | 0.30 → 0 | Dead-time fraction (audio pipelines only) |
| `bands.latency` | 30 → 5 | Topic open → decision, minutes |
| `bands.offAgenda` | 0.40 → 0.05 | Off-agenda talk fraction |
| `bands.pace` | 40 → 0 | Avg WPM outside the 130–170 band |
| `bands.filler` | 8 → 1 | Filler words per 100 words |
| `bands.respLat` | 60 → 5 | Median answer latency, seconds |
| `bands.monologue` | 0.80 → 0.30 | Longest turn ÷ presenter talk time |
| `bands.density` | 2 → 12 | Speaker turns per 10 min |
| `bands.feedback` | 0 → 8 | Feedback instances per meeting |
| `bands.chat` | 0 → 1 | Substantive chat messages per attendee |
| `bands.interrupt` | 6 → 0.5 | Overlaps > 2 s per 10 min |
| `mpiBands` | ≥85 Highly Productive · ≥70 Productive · ≥50 Needs Improvement · else Ineffective | MPI labels |

Normalization is always `clamp(100 · (value − worst)/(best − worst))`; ratios in \[0,1] where higher is better score as `value × 100`. **Calibrate once, then freeze** — comparability across meetings depends on a stable config, and the method footer prints it in every report for audit.

Other tuning points, each clearly labeled in the source: `RX` (regex lexicons for decisions, actions, deferrals, proposals, risks, feedback, fillers), `NOTNAME` (words never treated as speaker names), `STOPW` (agenda-keyword stopwords), the condensed-transcript threshold (`density < 0.5`), extraction caps (12 agenda items, 12 participants, 6 presenters, 6 decisions, 8 actions), visual theme (CSS variables in `:root`), and header branding text. The connected edition additionally exposes `CONFIG.model` and `CLAUDE_CHAR_LIMIT` (60,000 chars).

**Keeping the ecosystem in sync.** The companion Excel workbook (`mpef-meeting-scorecard.xlsx`, Config sheet) and agent spec (`mpef-agent-spec.md`, §3) carry the same defaults. If you change bands or weights, change them in all three so every implementation of the framework produces matching scores.

## 7. Verifying a deployment

Open the file and confirm the dark header reads **engine v2.5** — the filename never changes between versions, so this stamp is the only reliable build check. Then press **Sample → Extract & score locally**: on an unmodified v2.5 build this deterministically renders **MPI 70.92 · Productive** (unchanged from v1.4), six scored dimensions each with a hover/focus tooltip explaining what it measures, a Participation table of 6 (not 8) attendees with a disclosure line for the 2 silent ones and a Contributions cell reading `Q·A·P·R·I·D·T` for each, a `⋯` button on each row opening a full participant detail page, an **Agenda drift by member** card directly below it, and a flags panel that includes the condensed-transcript and off-agenda-keyword-matching disclosures — the dashboard ends there; it no longer carries its own Decisions, Action items, or Attendee questions cards. Open a participant's detail page and confirm all seven of Questions asked/Answers given/Proposals/Risks/Info/Decisions stated/Actions owned are present, in that order, and that each section's item count matches the letter it corresponds to in that person's Contributions cell (e.g. Sara's `Q0 · A1 · P1 · R1 · I2 · D2 · T0` — zero items under Questions asked, one under Answers given, and so on) — this parity is the point of v2.2. To check v2.3's transcript reader, paste a two-line block transcript in either order (`02:32:23  The respective team` / `The Chairman 01:19:06`, each followed by a line of speech) and confirm the Participation table lists those labels as speakers rather than reporting no speaker labels. On the Sample, confirm Agenda drift by member shows Karl's one off-topic question (deferred) and that its per-member table rows sum to the same off-agenda minutes shown in the tiles. To check v2.5's speaker fold, paste a transcript that spells one person two ways (`Sara:` and `sara:`) and confirm the Participation table shows one row, not two, credited to the capitalized spelling. Click **العربية** at the top-left to switch the whole UI and report to Arabic (RTL, right down to the Sample meeting itself) and back; the choice is not persisted (§10). Full acceptance steps live in the companion checklist.

For the offline edition you can additionally prove network silence: search the file for `fetch(` — the only permitted match is none at all. (A bare search for `http` is not the right test: the file legitimately contains a URL-detection regex, `/^https?/i`, used to keep a pasted link from being mistaken for a speaker name.) Or open it with the browser's network tab recording and confirm zero requests beyond the file itself.

## 8. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Header doesn't say engine v2.5 | Stale copy (identical filename) | Replace the file; re-share the zip |
| UI is back in English after a reload | By design — language is a display setting, not persisted (§10 no-storage guarantee) | Click **العربية** again; this is expected, not a bug |
| Flags panel / Any-AI prompt text is still English while the rest of the UI is Arabic | Known v2.0 scope boundary — see §16 | No fix needed; the underlying data (agenda titles, decisions, transcript quotes) is already in whatever language you pasted |
| Agenda item shows "not found" | Wording differs from the agenda (paraphrase), or genuinely wasn't discussed | Check the flags panel entry naming it; if it *was* discussed, correct `located`/`substantive`/`evidence` in the editable step-2 JSON and re-score, or rephrase the agenda line closer to the transcript's wording |
| A real decision is missing from the Decisions card | The disqualifier set (§4 rule 10) rejected the line — often a hedge like "we should" or "let's decide later" sitting next to real decision language | Add or correct the decision directly in the editable step-2 JSON (`outcomes.decisions[]`) and re-score |
| "Couldn't parse any utterances" | Unrecognized transcript layout | Use `[10:04] Name: text` lines, or paste the raw platform export (VTT/SRT and speaker/timestamp blocks in either order are auto-detected) |
| Many metrics show n/a | Honest-measurement rules (§4) fired | Read the flags panel; supply richer artifacts (verbatim transcript, second-level timestamps, attendance log) or use Route B |
| Scores look extreme (0/100) with counts like 1/1 | Genuine tiny-sample ratios | Judge by the printed counts; more countable events → finer scores |
| "rate-limited" after several Claude runs | API throttling (connected edition) | The app retries automatically; wait ~1 min if it persists |
| "can't reach the Claude API from here" | File running outside Claude / offline | Expected — use Route A or B, or the offline edition |
| Giant prompt won't paste into an AI chat | Chat input limit | Use "Save as .txt" and attach the file to the AI instead |
| Nothing saved between sessions | By design (privacy) | Keep source artifacts; use "Print / save as PDF" to keep reports |

## 10. Data handling

All parsing, scoring, and rendering happen in the browser tab. The offline edition performs zero network activity by construction. The connected edition transmits pasted artifacts to the model **only** when the user presses "Analyze with Claude". No cookies, no localStorage, no analytics; closing the tab erases everything. Reports can be anonymized upstream by replacing names in the artifacts, or with the **Anonymize participants** checkbox on the Meeting card, which renders the Participation table (and, since v2.0, each participant's detail page) as P1, P2… (agent spec §1/§5) — presenter names and decision/action owners are intentionally left as-is, since the spec names only participant-facing tables as anonymizable. This same no-storage guarantee is why the **language choice** (v2.0) is never persisted: it is UI state held only in the running page, exactly like the anonymize checkbox or any unsaved form field — reloading or reopening the file always starts in English.

## 12. Fixes and additions in this repository (since the uploaded v1.3 build)

Cross-checking the app against `mpef-agent-spec.md` and `mpef-meeting-scorecard.xlsx` (§3 of both) surfaced a handful of gaps, closed without changing any scoring formula, weight, or band:

- **D7 Follow-Through** (spec §3: prior-action closure, topic recurrence) is now scored from an optional "Advanced evidence" card — weight 0, deliberately excluded from the per-dimension average and the MPI, verified against the workbook's own D7 numbers.
- **Flag evidence citations** (spec §1/§5: "citing a timestamp or line reference for every figure and flag") — the `agenda_items` schema gained an `evidence` field, and unresolved-item / missing-owner / decision-not-made flags now cite it.
- **Anonymize toggle** — see §10 above.
- **Manual dead time / off-agenda / interruption-rate inputs** — these three metrics are honesty-gated (§4 above) and the local route could never populate them; a user who has the real numbers from an audio pipeline can now enter them directly, same override precedence as scheduled minutes and invitee count (extraction JSON wins if it already has the field, the manual input is the fallback).
- **File import** for all five artifacts and the step-2 JSON box, plus **download extraction JSON** and **download report (.html)** — the downloaded report is a self-contained snapshot (embeds the page's own stylesheet, plus, since v2.6, every participant's pre-rendered detail page wired up with pure-CSS `:target` navigation — see §22) that renders identically opened standalone, with no dependency on the app itself and no `<script>` of any kind.
- **Two Route-B correctness bugs**, found by scoring pasted JSON against a leftover browser tab: `compute()` was reading the attendance textarea's raw text as a fallback signal, letting attendance/active-contributor metrics score off speaker-only evidence in violation of the attendance-grounding gate; and the "Minutes/Chat/Attendance not provided" flags read the intake textareas instead of the JSON actually being scored, so they could contradict data the JSON supplied. Both now derive strictly from the extraction payload.
- **Honesty-note prioritization** — the local engine can fire more disclosures than the spec's 6-note budget allows; they are now dropped by priority (a meeting-specific honesty-gate finding always survives ahead of generic boilerplate) instead of arbitrary push order.
- **A regression suite** (`test/run.js`, no dependencies) pinned two golden fixtures at the time — the app's own Sample meeting (MPI 75.13, since moved to 70.92 by §13 below) and the workbook's example meeting (MPI 77.167458, all 27 metrics matched to the workbook's cached formula results to 1e-6) — plus the six evidence-honesty gates, seven transcript formats, and the fixes above.

Two items were investigated and deliberately **not** changed: the workbook's Gini coefficient uses a rank-based tie-handling approximation that can overstate speaking balance by 15–17 points when talk times tie (the app computes it exactly); and the sequence-adherence / pace-deviation metrics are position-match and average-WPM proxies in both the app and the workbook, standing in for the framework's LCS and per-minute in-band-share measures respectively (`meeting-performance-evaluation-framework.md` was not available to confirm whether either implementation already matches it). Both are documented in the app's own method footer.

## 13. Engine v1.4 changes (multi-presenter, honesty gates, decisions, questions, off-agenda)

A second pass, driven by real usage, closed five more gaps — again without touching any weight or band:

- **Multi-presenter agenda items.** `lxParseAgenda()` used to keep a single owner string; `"Sara & Amir"` was stored verbatim and then failed the speaker-match entirely, silently dropping both presenters. Owner segments are now split into an `owners` array (`&`, `,`, `and`), each name validated individually, so **every** matched speaker is credited — each against the item's full planned minutes, with a disclosure note whenever an item has 2+ presenters (splitting evenly instead is a one-line change if you'd rather divide the planned time). `owners` is now part of the extraction schema and shown as a Presenter column in the Agenda coverage map.
- **Zero-count honesty gate.** `feedback_instances` used to always be a number — `0` when the detector found nothing — which scored a hard 0/100 on band `[0,8]` and could drag D5 down at weight 10 on no real evidence. It's now `null` when nothing is detected, dropping the metric out of D5 with a disclosure note, the same pattern already used for question-resolution. The same fix applies to agenda items the keyword matcher couldn't locate: they now count as **not covered** for Coverage rate (a real finding) but their own time adherence is Not Assessable rather than a false 0.
- **Decisions: full text + speaker.** The 80-character clip on decision text is gone — decisions render as complete sentences, wrapping in the Decisions card — and each now carries the speaker who stated it (`outcomes.decisions[].speaker`), shown as a bold prefix, matching how actions already show their owner. Decision speakers are never anonymized, consistent with action owners.
- **Questions named in Flags.** Unanswered and deferred questions used to render as a bare count ("3 questions left unanswered"). A new `interaction.questions[]` array (text, asker, status, responder, evidence) lets the flags panel list each one individually with its evidence citation. Answered questions remain a count. This also fixed an honesty-gate bug: on transcripts with no speaker labels, `questions_answered`/`questions_deferred` are correctly `null`, but the unanswered-count flag coerced that to 0 and flagged **every** question high-severity — directly contradicting the "not assessable" note fired in the same run. It now correctly reports Not Assessable.
- **Off-agenda by keyword matching.** Local extraction scored this permanently Not Assessable, reasoning that true off-agenda detection needs semantic understanding the keyword engine doesn't have. Per user request it's now scored anyway: each substantive utterance (≥8 words) that matches none of the agenda's keywords counts as off-agenda time, always accompanied by a disclosure note that this is proximity matching, not semantic analysis. A manually-entered value (Advanced evidence card) still takes precedence. This activates a fourth D1 metric that was previously always excluded, which is why the Sample acceptance MPI moved from 75.13 to **70.92**.
- **Two bugs found and fixed along the way**, both in code this pass already touched: two agenda items whose keywords matched the *same* utterance used to produce an empty span and crash on `evi(undefined)` — utterance anchors are now guaranteed unique; and the unanswered-question flag's `||0` coercion (above) that defeated the no-speaker-labels honesty gate.
- The regression suite grew to 127 checks (`test/run.js`) covering every item above, including both incidental-bug regressions.

## 14. Engine v1.5 changes (agenda-anchoring rewrite, honest "not found")

A report that a discussed item showed **skipped** led to an audit that found seven distinct paths to that one wrong label, all traced to the same design flaw: `substantive` was a single boolean carrying three incompatible meanings — *genuinely not discussed*, *couldn't be located*, and *located but the span looked thin* — and all three rendered as the identical grey dot. Because `substantive` also drove the Coverage rate score, the unresolved-items ratio, and the high-severity "Unresolved" flag, every false skip quietly deflated D1 and the MPI too.

- **Anchoring rewritten as scored best-overlap, not first-hit.** The old anchor for each agenda item was whichever utterance happened to contain the *first* raw substring match of a keyword, in agenda order. That made a passing early mention ("we'll come back to the budget later") steal the anchor from the item's real 12-minute discussion later on, and made two items competing for the same utterance orphan whichever lost. Anchoring is now a global assignment: every item is scored against every utterance by shared *stemmed* keywords (light suffix stripping, so *forecast/forecasting/forecasts* unify), candidates are sorted by score, and assignment proceeds best-score-first with each utterance claimed once. A title like "Q3 review" that used to yield zero usable keywords (both words are stopwords under the old ≥3-char/non-stopword filter) now falls back to raw tokens so it can still match.
- **`substantive` redefined by span word count.** Turn-count (`span.length >= 2`) and a 1-minute clock floor used to gate this, both of which fail for reasons that have nothing to do with whether real discussion happened: a topic covered thoroughly in one long turn, two anchors landing in the same displayed minute under minute-granularity timestamps, or a no-timestamp transcript where the same floor becomes an undisclosed ~140-word requirement via the word-count time estimate. The gate is now purely spoken-word count in the matched span (with a recorded decision or action always counting as substantive in its own right, regardless of length) — the same test with or without timestamps, immune to where a neighboring item happens to anchor.
- **"Not found" is now a distinct, honest status.** An item the matcher genuinely cannot locate anywhere in the transcript still counts against Coverage rate (excluding it would let a truly-skipped item hide the same way), but no longer renders as **skipped** — it renders as **not found**, in its own color, with a flag naming every such item so a paraphrase mismatch (different wording than the agenda) is visible and correctable in the editable step-2 JSON, rather than silently misreported as a factual finding about the meeting.
- **Zero-minute last-item guard.** The final agenda item's actual-minutes used to be computed against the meeting's end timestamp, which can legitimately compute to 0 under minute-granularity stamps even though real content was spoken; it now falls back to the same word-count time estimate used on the no-timestamp path when that happens.
- The regression suite grew to 141 checks (`test/run.js`), including one test per failure mode identified in the audit and a canary confirming a genuinely-skipped item (the Sample's "AOB", explicitly deferred in the transcript) still reads as skipped after the rewrite.

## 15. Engine v1.6 changes (silent attendees, verified decisions, attendee questions)

Three requests against v1.6's report read-out, all display-side except one that also tightens what counts as a decision:

- **Silent attendees no longer clutter Participation.** An attendee present in the attendance log who never spoke used to sit in the table at a flat 0.0% talk share, indistinguishable from real signal. Rows are now dropped only for a *positively-measured* 0% — a `null` share (talk time genuinely unmeasurable) is never touched, same honesty gate as everywhere else in the app — and a line under the table discloses the count: *"N attendees present with no recorded speech are not listed — they still count in attendance rate, active contributors and speaking balance."* D4 scoring is unaffected; this is a display-only filter over the same full participant list.
- **Decisions are verified, not just pattern-matched.** The trigger regex (`agreed`, `approved`, `we go`, `decided`, `ship it`, …) used to count anything it matched. It now has to survive explicit disqualifiers first — see §4 rule 10 above — before being counted at all, closing a real gap: a plain "Agreed." with no stated outcome, or "we should approve this," used to score exactly like a real decision taken. This does reach scoring (MoM fidelity in D6, and decision-driven `closed`/coverage in D1 and D6), though the Sample's own three decisions all survive unchanged, so its acceptance MPI is unmoved. Surviving decisions are then enriched with **time**, the **agenda item** they were made under, 1-3 lines of surrounding **context**, and a **basis** stating what qualified them (the trigger phrase, plus any action item or minutes line that corroborates it) — rendered as their own full-width card instead of a two-column split with Action items, since the record now needs the room. Cap raised from 6 to 20 decisions.
- **New "Attendee questions" section.** Every question is now listed grouped by who asked it, each with its resolution status and responder, the agenda item under discussion when it was asked, the question-and-answer in context, and a three-state **topic match**: *on topic* (its content overlaps the discussion it was asked in), *other item (X)* (it doesn't match its own discussion but clearly names a different agenda item — catches a question asked in the wrong slot), or *no keyword match* (neither — deliberately not "off topic," since keyword proximity can't support that stronger claim, same posture as v1.5's "not found"). Cap raised from 12 to 24 questions; `questions_raised` itself was never capped, so no metric moves.
- **Anonymize participants now covers both attendee-keyed sections.** The toggle previously only renamed the Participation table. Attendee questions' asker and responder names are now anonymized the same way (question text itself is never altered); Decisions and Action items remain deliberately un-anonymized, unchanged from v1.4 — that scoping is unaffected.
- Route B's schema gained the same fields (`decisions[].time/agenda_item/context/basis`, `questions[].agenda_item/context/topic_match`) with a matching rule on what does and doesn't qualify as a decision; a pasted JSON missing them still scores and renders correctly (all new fields are read defensively).
- The regression suite grew to 171 checks (`test/run.js`), covering the disqualifier set, the enrichment fields, all three topic-match states, the silent-attendee filter (including the null-share non-regression), and Route B back-compat.

## 16. Engine v2.0 changes (tooltips, Arabic capture, Arabic UI, participant drill-down)

Four requests, one of them a real capability gap rather than a display feature:

- **Metric tooltips.** All 29 scored metrics and all 6 dimensions now carry a small ⓘ that shows a one-sentence explanation on hover or keyboard focus (and tap-to-toggle on touch) — what it measures, what evidence it needs, which direction is better. Pure CSS/HTML (a hidden checkbox drives the touch toggle), so it survives "Download report (.html)" intact with no JavaScript dependency.
- **Arabic transcript capture — the actual gap this release closes.** Before v2.0 an Arabic transcript produced nothing: zero speakers, zero decisions, every agenda item unlocatable. Every layer failed independently — the speaker-name pattern required a Latin capital (Arabic has no case), question detection only recognized `?` not `؟`, the agenda/topic tokenizer stripped Arabic to zero tokens, and every decision/action/risk/feedback detector was an English word list. All of it now has an Arabic counterpart, matched per token so a code-switched sentence ("اتفقنا — we ship the API by Friday") is caught by whichever language it's actually written in: an Arabic name pattern alongside the Latin one, `؟` alongside `?`, Arabic-Indic digit folding for timestamps and agenda durations, an `arNorm()` normalizer (alef/teh-marbuta folding, definite-article and suffix stripping) as the Arabic sibling of the English stemmer used for agenda anchoring and topic-matching, and a full Arabic lexicon for decisions, actions, deferrals, risk, feedback and proposals. Filler-word detection stays English-only (no dependable Arabic filler lexicon exists), so it now reports Not Assessable — not a false low count — the moment a transcript is majority Arabic, with a disclosure note naming the detected script mix. A second, equally-thorough Arabic sample meeting demonstrates the whole pipeline end to end.
- **Arabic UI with a language switch.** A control fixed at the top-left of the viewport (independent of `dir`, so it never moves when you switch) toggles the entire interface — every label, button, table header, status word, band name, and the report itself — between English and Arabic, with `dir="rtl"` and logical CSS properties so the layout mirrors correctly; numeric/mono cells (scores, timestamps, evidence references) stay pinned left-to-right inside the RTL page so times and score fractions don't visually scramble. Switching re-renders the *same already-computed* model — `band`, `status`, and `topic_match` stay canonical English values internally (so Route B round-trips and the golden fixtures are untouched), translated only for display. **Known boundary:** flags-panel messages and disclosure notes, and the Any-AI extraction prompt's instructional text, are generated once at extraction/compute time in whichever language was active then, and remain in that language if you switch afterward — they are not a second parallel translation layer, unlike everything else in this list.
- **Participation counts + participant drill-down.** The Participation table gained three columns (questions asked, decisions stated, actions owned) computed at render time from data the report already has, so pasted Route B JSON gets them for free. A `⋯` button per row opens a full-page detail view for that person — talk share, presenter role, every question they asked and answered, every decision they stated and action they own, their chat messages, their off-agenda-tagged contributions, and a complete timestamped timeline — with a Back button returning to the same report (no re-extraction). The two new extraction fields this needed, `participants[].chat` and `participants[].timeline` (capped at 40 entries, `null` on legacy JSON or in pseudo/no-speaker-labels mode), are purely additive and never touch scoring.
- The regression suite grew to 207 checks (`test/run.js`): 19 for Arabic capture (speakers, `؟`, Arabic-Indic digits, `arNorm`, code-switching, the not-a-name guard, the full Arabic Sample end to end), 8 for tooltips/i18n key-parity, 9 for the count columns and drill-down page (including a legacy-JSON graceful-degradation check).

## 17. Engine v2.1 changes (participant-page context, dashboard cards retired)

Two requests against the v2.0 build's report read-out, both presentation-only — no metric, weight, band, or extraction rule changed:

- **The participant page now shows its evidence, not just its conclusions.** Questions and answers used to render as bare one-liners even though the extraction already carried a `context` array for each. Questions asked now show the answer received (`context[1]`), the resolution status, and the `topic_match` label; answers given show the question that was being answered, with the participant's own answer as context underneath. Off-agenda contributions gained the one thing readers most needed and didn't have: *why* — stated as the rule that actually ran ("an 8-word contribution, matching none of the agenda's keywords (...)"), naming the actual keyword list via a new `quality.agenda_keywords` extraction field (`null` when off-agenda wasn't assessable at all; absent on pre-v2.1 Route B JSON, which falls back to a generic sentence). Decisions stated deliberately stayed agenda item + text only: an early draft of this release added the same treatment there — the 1-3 preceding transcript lines (`context.slice(0,-1)`) plus the **basis** that qualified the decision — but that buried the decision itself under an exchange already shown in full further down the same page's Timeline, so it was reverted; `context` and `basis` remain in the extraction JSON for anyone auditing a decision.
- **Decisions, Action items, and Attendee questions no longer duplicate themselves on the dashboard.** All three were full-width cards on the main report repeating what each person's detail page now shows in richer context. They're retired; the report is now hero → dimension scores → metric table → agenda coverage → presenters → participation → flags → method. The Participation table's `⋯` button is the only route to per-person detail, and the flags panel still lists unanswered/deferred questions and unresolved items by name, so nothing action-oriented was lost.
- **The unattributed catch-all.** Some items can't be tied to any person at all — an action with a due date but no owner, any decision in a transcript with no speaker labels, or a Route B name absent from `participants[]`. With the three cards gone, those would vanish from the rendered report entirely now that detail is reachable only from a Participation row. A new compact card, rendered only when non-empty, lists exactly those (matched by the same name-prefix tolerance already used for the Participation table's decision/action counts); on a normal meeting like the Sample it renders nothing.
- The regression suite grew to 214 checks (`test/run.js`): the five checks that used to exercise the removed dashboard cards were retargeted at the participant page and the new catch-all card, plus new checks for the off-agenda reasoning, the legacy-JSON `agenda_keywords` fallback, and the catch-all card's presence/absence.

## 18. Engine v2.2 changes (one source of truth for contributions)

A user question — "why does the Contributions column show a different question count than the participant page?" — traced to a real bug, not a display quirk:

- **Two independent sources for the same numbers.** The Contributions cell read `participants[].questions`/`.answers` — the uncapped per-utterance counters that also feed D4 Active contributors. The participant detail page instead filtered `interaction.questions[]`, an enriched array capped at 24 entries. They agreed on the Sample (3 questions, well under the cap) but diverged on any transcript with more than 24 questions from one speaker — reproduced with a 30-question transcript: the cell said `Q30`, the page listed 24. Proposals, Risks and Info had no detail-page section at all despite being counted in the cell.
- **Fixed at the source.** A single `utterKind()` classifier (mirroring the exact arithmetic the counters already used — question if it contains `?`/`؟`, else proposal/risk if it matches that language, else info if ≥10 words, else uncounted) now tags every `participants[].timeline[]` entry with `kind`, and the Q&A-pairing pass tags the responding utterance with `answer` (§2 schema). Questions asked, Answers given, Proposals, Risks and Info on the participant page are all rebuilt from those tags — joined to the enriched `interaction.questions[]` record when one exists (for status/`topic_match`/the answer text), falling back to the bare utterance when it doesn't (past the cap, or on legacy JSON via the same `utterKind()` re-derivation). The result: every letter in the Contributions cell now has a matching section whose rendered item count equals it, verified for every Sample attendee.
- **Two honesty disclosures come with this.** An answer is also counted under its own contribution type (a footnote on Answers given says so — Sara's one answer is also one of her Info items, and both sections legitimately show the same utterance). And a section can render fewer items than its counter only when a speaker's utterances exceed the 40-entry timeline cap, in which case a footnote states "Showing N of M" rather than silently under-displaying.
- **The Participation table's standalone Q/D/A columns are gone.** D (decisions stated) and T (actions owned — `A` was already taken by Answers) join the Contributions cell instead, so the full shape of a person's participation — `Q·A·P·R·I·D·T` — lives in one place, with a tooltip spelling out all seven letters.
- The regression suite grew to 224 checks (`test/run.js`): a parity check looping every shown Sample attendee, asserting each of the five timeline-driven sections renders exactly as many items as its matching Contributions-cell counter; checks for the removed columns, the cell's exact expected values, and the extraction-level `kind`/`answer` tags; and a legacy-timeline test confirming a JSON predating v2.2 still classifies correctly via the `utterKind()` fallback while Answers given — which needs Q&A pairing, not derivable from text alone — stays empty rather than guessing.

## 19. Engine v2.3 changes (transcript reader accepts any block layout)

A transcript pasted in a common recorder layout scored as if nobody had spoken. Two separate causes, both in input normalization:

- **Only one block ordering was recognized.** `normalizeTranscript()` understood a speaker-first header (`Sara 0:04`, the Teams shape) but had no rule for the timestamp-first one (`02:32:23  The respective team`) that most recorder and minutes exports emit. A timestamp-first file fell through to the caption path: the speaker label was absorbed into the utterance text, `has_speaker_labels` came back `false`, and every participation, presenter and Q&A metric went Not Assessable — a full report's worth of evidence silently discarded. Both orderings now share one `headerOf()`, used for detection and parsing alike so a line can't be counted as a header and then parsed as something else.
- **A speaker label had to look like a person's name.** The header pattern required title case on every word, so "The respective team", "PMO lead" or "Facilitator" didn't qualify. Speaker-first blocks with such a label were worse than mis-parsed — they matched no rule at all and the whole transcript came back empty. A new `isSpeakerLabel()` accepts any label of up to 5 words / 48 characters that starts with a capital (or any Arabic letter), carries no terminal sentence punctuation, and isn't a not-a-name word — so a line of speech can't pose as a speaker.

**The safety boundary is what makes this affordable.** The loose label only ever applies to a line holding *nothing but* a bare timestamp and the label, and `lxParseTranscript()` only re-reads it loosely when `normalizeTranscript()` has already certified the text as block/export format (the new `blockFmt` argument). A bracketed `[10:04] …` line stays the inline caption convention, so caption-only input keeps its honest "no speaker labels" verdict, and an inline line like `[10:03] In summary: we shipped` is still speech, not a speaker called "In summary". Arabic-Indic digits are folded before detection, so Arabic block transcripts work in both orderings too.

- The regression suite grew to 233 checks (`test/run.js`): both orderings, a lowercase-containing label in each, multi-turn attribution across alternating speakers, ALL-CAPS and initialled names, Arabic-Indic block headers, plus three negative checks that a sentence, a not-a-name label word, and an inline colon-y caption line are each never read as a speaker.

## 20. Engine v2.4 changes (Agenda drift by member)

A new report section, requested to show who drove a meeting off its agenda and how the resulting off-topic questions were resolved — modelled on a PIF slide brought in as a reference, but built entirely from what the engine measures rather than the slide's illustrative numbers.

- **Almost nothing new to extract.** `interaction.questions[].topic_match` (v1.6) already verdicts every question against the agenda item under discussion, and `participants[].timeline[].off_agenda` (v2.0) already flags which utterances drifted. The one genuine gap was off-agenda *minutes per person* — the timeline knew which utterances drifted but not how long each ran, so a per-member split couldn't be derived at render time. `participants[].off_agenda_minutes` closes it: summed in the same per-speaker loop that already builds `talk_minutes`, and `null` under the identical condition `meeting.off_agenda_minutes` is already `null` — a false zero here would be exactly the honesty violation that global figure already guards against.
- **"Unclear" stays separate from "off-topic."** The card's off-topic tile counts only the `topic_match: "other item (...)"` verdict — a question the keyword engine flagged as clearly belonging elsewhere. `"no keyword match"` means the engine couldn't tell either way, so it renders as its own Unclear count rather than being folded into drift; asserting it as off-topic would be a stronger claim than a keyword-proximity read can support, the same posture `topicMatchLabel()` already holds everywhere else it's shown.
- **Two independently gated halves, one skip condition.** The question half needs speaker labels (`interaction.questions` non-null); the talk half needs off-agenda to be assessable (`off_agenda_minutes` non-null, globally and per person). Either renders alone when only one is assessable, each with its own Not Assessable message; the whole card is omitted, not shown empty, only when both are gated at once.
- **The bar chart is table markup, not SVG.** Each attendee's row scales to the busiest talker (so relative talk time is visible at a glance) and splits into on-agenda (teal) / off-agenda (coral) segments sized to that person's own minutes — a pairing chosen because it's the one categorical pair in the app's existing palette that passes every check in Anthropic's dataviz colorblind-safety validator (protan ΔE 8.2, normal-vision 27.6, contrast ≥ 3:1; the app's green fails the deutan floor against coral). Built from plain flexbox divs like the Participation table's share bars, so it survives "Download report (.html)" and print with no library dependency.
- The regression suite grew to 240 checks (`test/run.js`): per-person minutes summing to the scored global on the Sample; the card naming Karl's one other-item question and reporting it deferred; a "no keyword match" question never counted as off-topic; the card's absence when both halves are gated and its graceful one-half rendering when only one is; and a legacy Route B JSON predating the field still rendering without throwing.

## 21. Engine v2.5 changes (case-insensitive speaker identity)

A user question — "Sara and sara, aren't they the same person?" — traced to a real gap, not a display quirk: they weren't the same person, because nothing in the pipeline folded them.

- **A lowercase variant wasn't a second participant — it was unattributed text.** `NAME_LATIN` requires a capital on every token, so `sara:` never registered as a speaker label at all. The line's minutes and words still counted toward meeting totals, but belonged to nobody: with a timestamp, the utterance came back `sp: null` (its raw `"sara: "` prefix left sitting in the text); with no timestamp, it was worse — silently glued onto the *previous* speaker's turn as a continuation, inflating their word count and talk time with someone else's words.
- **Fixed at the root, not patched at each use site.** `localExtract` builds its speaker roster at one choke point, immediately after parsing — folding case variants there, before that roster is built, is the single change that makes every downstream reference agree: `perSp`/`timelineBySpeaker` keying, the Q&A pairing's asker/responder comparison (a question "answered" by a case variant of its own asker is now correctly a self-answer, not a real exchange), the presenter loops, and `decisions[].speaker`. The capitalized spelling always wins for display; if every occurrence is lowercase, it's title-cased. Arabic is untouched — there's no case to fold, so the first-seen spelling simply stays.
- **Recognizing the lowercase label at all is anchored, never a blanket relaxation.** `[time] name: text` is now accepted case-insensitively, but only once `Name` is already an established speaker elsewhere in the same transcript — a second parse pass tries the anchored pattern and is kept only when it strictly improves attribution, so it can never make things worse. Loosening the shape requirement itself (accepting any lowercase-starting label unconditionally) was explicitly rejected: it would let ordinary prose ("so: we should ship it soon") parse as a speaker. An all-lowercase transcript with no capitalized occurrence anywhere to anchor to is not rescued by this rule and correctly stays Not Assessable — a deliberate boundary, not an oversight.
- **The same anchor reaches agenda owners, chat, and attendance.** All three already *matched* names case-insensitively — they just couldn't *capture* a lowercase one. A lowercase agenda presenter ("— sara —") no longer loses their D3 credit; a `sara:` chat line and a `sara 10:00 - 10:45` attendance line both land on Sara. One honest limit stays documented rather than papered over: a silent attendee named *only* in the attendance log, in lowercase, has no speaker to anchor to and is still not captured — relaxing that regex unanchored would let any word followed by two clock times become an attendee.
- The regression suite grew to 252 checks (`test/run.js`): the fold with and without timestamps, the self-answer correction, the anchor boundary (prose never becomes a speaker), the all-lowercase-with-no-twin boundary, agenda/chat/attendance anchoring, the documented attendance-only limit, and Arabic names confirmed untouched.

## 22. Engine v2.6 changes (the downloaded report keeps its drill-down)

A user report — "I download the report, open the file, and the `⋯` button in the Participation table does nothing" — traced to "download report (.html)" saving markup and the stylesheet, but no `<script>`.

- **The saved file was never able to run the drill-down.** `renderParticipant()`, `lastModel`, and the delegated click listener that calls them only exist in the live app's `<script>` block; `downloadReportHtml()` copied out `document.getElementById("report").innerHTML` and the page's `<style>` tag, nothing else. Every `⋯` button's `data-pname` attribute survived the copy, but with no script to read it, the button was just inert markup — and the copied "Download report" button itself would have thrown `ReferenceError` had anyone been able to click it.
- **Fixed by pre-rendering, not by shipping a script.** The saved file stays a genuinely standalone, zero-`<script>` document — that guarantee wasn't up for negotiation. Instead, `renderParticipant()`'s body was split into a pure builder, `participantDetailHtml(name, opts)`, that returns a detail page's HTML as a string (or `null` for an unknown name or no model yet) without touching the DOM. A new `buildReportFileHtml()` calls it once per participant *at download time*, while `lastModel` and every rendering helper are still live, and assembles the result with pure-CSS `:target` navigation: each `⋯` button becomes a plain `<a href="#pd-...">`, every pre-rendered detail page is `display:none` until it's the URL fragment target, and a sibling selector (`.pdPage:target ~ #pd-home`) hides the dashboard whenever one is showing. The Back link (`opts.backHref`) is a plain anchor back to `#pd-home` instead of the in-app `#pdBackBtn` button. All of this runs on a detached clone of `#report`'s markup, so building the file never touches the page the user is looking at.
- **Anchor ids never leak a real name.** `pdSlug(displayedName, rowIndex)` builds each page's id from the *displayed* participant-table cell text — so an anonymized report's anchors read `#pd-p1-1`, never `#pd-sara-1` — with the row index appended to disambiguate duplicate names and non-Latin names that slug to nothing.
- **Two smaller bugs fixed in the same pass, both display-only:** the saved file was always `<html lang="en">` with no `dir` attribute, regardless of the app's language when downloaded — now taken from `document.documentElement` at build time, so an Arabic report downloads `lang="ar" dir="rtl"`. And the anonymize toggle's `dispName()` closure was built independently by `render()` and by the old `renderParticipant()`, each starting its own P1/P2… map from scratch — the person shown as P3 on the dashboard could be titled P1 on their own detail page, whichever name each view's map happened to see first. `anonNamer(model, anonOn)` replaces both: one map, seeded once in participant order, shared by every call site that needs a display name.
- The regression suite grew to 262 checks (`test/run.js`): `participantDetailHtml()`'s null-return guards and its parity with `renderParticipant()`'s in-app output, the button-vs-anchor back-link swap, `pdSlug()`'s uniqueness and non-Latin fallback, and the anonymize numbering now agreeing between the dashboard and a participant's own page. The saved file's actual `:target` navigation — dashboard hidden, correct page shown, Back link returning — was verified end to end in headless Chromium by writing `buildReportFileHtml()`'s output to disk and opening it as its own `file://` page, in English, Arabic, and with anonymize on, with zero console errors in every run.
